# מעקב הוצאות מהמייל · Mail Expense Tracker

אתר מקומי שמתחבר לתיבת הדואר שלך, מזהה אוטומטית מיילים של חיובים, קבלות
וחשבוניות, ובונה מהם מעקב הוצאות מלא — גרפים, קטגוריות, תקציבים וייצוא ל-CSV.

A self-hosted expense tracker that reads charge/receipt emails from your mailbox
and turns them into a categorised expense dashboard. Built for Israeli mail
(ישראכרט, כאל, מקס, בנקים, bit) as well as international receipts (PayPal,
Amazon, Apple, Google).

> **הכל נשאר אצלך.** הנתונים נשמרים בקובץ SQLite מקומי (`data/expenses.db`).
> אין שרת חיצוני, אין שליחת מידע לאף אחד, וההרשאה שמבוקשת מ-Gmail היא **קריאה בלבד**.

---

## מה זה עושה

- **סורק את הדואר** ומאתר רק מיילים שהם באמת חיוב — פרסומות ומבצעים מסוננים החוצה.
- **מחלץ** סכום, מטבע, בית עסק, תאריך העסקה, ו-4 ספרות הכרטיס.
- **מסווג אוטומטית** ל-16 קטגוריות (מזון, מסעדות, תחבורה, תקשורת, מנויים...).
  אפשר להוסיף כללים משלך שדורסים את ברירת המחדל.
- **מזהה זיכויים והחזרים** ורושם אותם כסכום שלילי.
- **מסמן כפילויות** — כשגם חברת האשראי וגם בית העסק שלחו מייל על אותו חיוב.
- **דשבורד**: הוצאה חודשית, ממוצע, פילוח לפי קטגוריה, בתי עסק מובילים, תקציבים.
- **ייצוא CSV** (עם BOM, כך שאקסל פותח עברית כמו שצריך).
- כל עסקה ניתנת לעריכה, הסתרה או מחיקה ידנית, ואפשר גם להוסיף הוצאות במזומן.

מיילים שהמערכת לא בטוחה לגביהם מסומנים **"לבדיקה"** במקום להיכנס בשקט לנתונים.

## התקנה

דרוש Node.js 20.6 ומעלה.

```bash
npm install
cp .env.example .env
```

### 1. סיסמה לאתר (מומלץ)

```bash
npm run set-password
```

הפקודה מדפיסה שורת `APP_PASSWORD_HASH=...` — העתק אותה ל-`.env`.
בלי סיסמה האתר פתוח לכל מי שמגיע לכתובת, ולכן זה בטוח רק על `localhost`.
כדאי גם להחליף את `SESSION_SECRET` למחרוזת אקראית ארוכה.

### 2. חיבור לתיבת הדואר

בחר אחת משתי הדרכים ב-`.env`:

#### אפשרות א׳ — Gmail API (מומלץ)

סריקה מהירה, ו-Google מחזיר רק מיילים שמתאימים לחיפוש, כך שנקראים הרבה פחות מיילים.

1. היכנס ל-[Google Cloud Console](https://console.cloud.google.com/) וצור פרויקט חדש.
2. תחת **APIs & Services → Library** הפעל את **Gmail API**.
3. תחת **OAuth consent screen** בחר **External**, מלא שם ואימייל, ובשלב
   **Test users** הוסף את כתובת הג׳ימייל שלך.
4. תחת **Credentials → Create credentials → OAuth client ID** בחר
   **Web application**, ותחת *Authorized redirect URIs* הוסף:
   `http://localhost:3000/oauth/callback`
5. העתק ל-`.env`:

```ini
MAIL_PROVIDER=gmail
GOOGLE_CLIENT_ID=...apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=...
GOOGLE_REDIRECT_URI=http://localhost:3000/oauth/callback
```

6. הרץ את השרת, ולחץ באתר על **"חיבור לחשבון Gmail"**.

ההרשאה המבוקשת היא `gmail.readonly` — קריאה בלבד. אי אפשר לשלוח או למחוק מיילים.

#### אפשרות ב׳ — IMAP עם סיסמת אפליקציה (פשוט יותר)

לא דורש פרויקט ב-Google Cloud, ועובד מול כל תיבה — לא רק Gmail.

ב-Gmail: הפעל אימות דו-שלבי, ואז צור **App Password** בכתובת
https://myaccount.google.com/apppasswords

```ini
MAIL_PROVIDER=imap
IMAP_HOST=imap.gmail.com
IMAP_PORT=993
IMAP_USER=you@gmail.com
IMAP_PASSWORD=סיסמת-האפליקציה
IMAP_MAILBOX=INBOX
```

הערה: IMAP לא תומך בחיפוש לפי מילות מפתח, ולכן המערכת מורידה את כל המיילים
מהתקופה הנבחרת ומסננת מקומית. הסנכרון הראשון יהיה איטי יותר מאשר ב-Gmail API.

### 3. הרצה

```bash
npm start
```

פתח את http://localhost:3000 ולחץ **"סנכרן עכשיו"**.

הסנכרון הראשון סורק 180 ימים אחורה (`INITIAL_SYNC_DAYS`). אחריו כל סנכרון
בודק רק מה שהתווסף מאז, עם חפיפה של יומיים למקרה שמייל הגיע באיחור.
סנכרון אוטומטי רץ כל 30 דקות (`SYNC_INTERVAL_MINUTES=0` מכבה אותו).

אפשר גם לסנכרן משורת הפקודה, למשל מתוך cron:

```bash
npm run sync
```

## איך הזיהוי עובד

הבעיה האמיתית היא לא למצוא מספר במייל — היא למצוא את **המספר הנכון**. קבלה
טיפוסית מכילה מע״מ, דמי משלוח, יתרת מסגרת ונקודות מועדון, וכולם נראים כמו סכום.

לכן `src/parse/money.js` אוסף **את כל אזכורי הכסף** במייל ונותן לכל אחד ניקוד לפי
המילים שסביבו, משוקלל לפי מרחק: `"סכום העסקה"` ו-`"סה״כ לתשלום"` מעלים את הניקוד,
ואילו `"יתרת מסגרת"`, `"נקודות"`, `"מע״מ"` ו-`"משלוח"` מורידים אותו. הסכום עם הניקוד
הגבוה ביותר מנצח; אם שום דבר לא סומן, נבחר הסכום הגדול ביותר והעסקה מסומנת לבדיקה.

`src/parse/parser.js` מחליט קודם כל **האם זה בכלל חיוב** — מייל שיווקי עם מחיר
נדחה, וחיוב אמיתי מזוהה לפי ביטויים כמו `"בוצעה עסקה"`, `"קבלה"`, `"Order Total"`.
אחר כך מחולצים בית העסק, הכרטיס והתאריך. חברת אשראי שמדווחת על חיוב **אינה**
בית העסק — הכלל הזה מטופל במפורש דרך `src/parse/senders.js`.

לכל עסקה מחושבת רמת ביטחון. מתחת ל-0.6 היא נכנסת כ-**"לבדיקה"** ולא כעובדה.

### הערה על עברית ו-Regex

`\b` ב-JavaScript מתבסס על `\w` שהוא ASCII בלבד, ולכן **כל אות עברית נחשבת
תו שאינו-מילה**. כתוצאה מכך ביטוי כמו `/ש"ח\b/` פשוט לא מוצא התאמה בסוף שורה.
הקוד משתמש במקום זה ב-lookarounds מפורשים: `(?<![\p{L}\p{N}])` ו-`(?![\p{L}\p{N}])`
עם הדגל `u`.

## מבנה הפרויקט

```
src/
  config.js          קריאת .env
  db.js              סכימת SQLite + עזרי settings
  auth.js            סיסמה (scrypt) ושמירת session
  server.js          Express, ניתוב, סנכרון מתוזמן
  routes/api.js      REST API
  routes/oauth.js    זרימת OAuth של גוגל
  mail/gmail.js      Gmail API (fetch בלבד, ללא SDK)
  mail/imap.js       IMAP + mailparser
  mail/sync.js       הורדה → פענוח → שמירה, כולל דדופליקציה
  parse/money.js     חילוץ סכום ומטבע עם ניקוד הקשר
  parse/parser.js    סיווג מייל וחילוץ עסקה
  parse/categories.js קטגוריות וכללי סיווג
  parse/senders.js   זיהוי חברות אשראי, בנקים וספקים
public/              ממשק המשתמש (HTML/CSS/JS, ללא תלויות חיצוניות)
test/                בדיקות ל-pipeline הפענוח
```

הגרפים מצוירים ב-SVG ישירות בקוד — אין CDN ואין ספריית גרפים, כך שהאתר עובד
גם בלי חיבור לאינטרנט.

## API

| Method | Path | תיאור |
| --- | --- | --- |
| `GET` | `/api/status` | מצב חיבור, מספר עסקאות, כמה ממתינות לבדיקה |

| `GET` | `/api/summary?months=12` | נתונים לגרפים ולכרטיסים |
| `POST` | `/api/sync` | סנכרון מיידי |
| `GET/POST/DELETE` | `/api/rules` | כללי סיווג |
| `PUT` | `/api/budgets` | תקציב חודשי לקטגוריה |
| `GET` | `/api/export.csv` | ייצוא |

## פתרון תקלות

| בעיה | פתרון |
| --- | --- |
| `redirect_uri_mismatch` | ה-URI ב-Google Cloud חייב להיות **זהה בדיוק** ל-`GOOGLE_REDIRECT_URI`, כולל הפורט |
| `invalid_grant` בסנכרון | ה-refresh token פג. התנתק והתחבר מחדש |
| Gmail: `Access blocked` | הוסף את עצמך תחת *Test users* במסך ההסכמה |
| IMAP: `Invalid credentials` | ב-Gmail חייבים **סיסמת אפליקציה**, לא סיסמת החשבון |
| חיובים לא נמצאו | הרחב את החיפוש דרך המפתח `gmail_query` בטבלת `settings` |
| סכום שגוי | ערוך את העסקה בטבלה, והוסף כלל קטגוריה לבית העסק |

## מגבלות ידועות

- סכומים נשמרים במטבע המקורי ולא מומרים; סיכומים מניחים מטבע אחיד.
  לתמונה נכונה בעסקאות מט״ח, סנן לפי מטבע או ערוך את הסכום ידנית.
- חיובים שאין עליהם מייל (הוראת קבע, מזומן) לא ייקלטו — הוסף אותם ידנית.
- זיהוי הכפילויות מבוסס על סכום ותאריך קרובים, ולכן שתי רכישות זהות באמת
  באותו יום יסומנו כחשודות ככפילות. הסימון לא מוחק כלום — רק מסמן לבדיקה.
